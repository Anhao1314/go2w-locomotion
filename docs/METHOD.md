# 量化方法论：从数据到决策的八步流程

[返回首页](../README.md) · [结果总表](RESULTS.md) · [因子库](FACTORS.md) · [实验协议](EXPERIMENT_DESIGN.md)

本仓库的每条结论都按同一套流程产生。它解决的问题很具体：**在没有这套流程之前，我们报出过 0.70，而真实值是 0.50。**

---

## 八步

### 第 1 步 · 把问题定义成可判定的量

**做什么**：一个问题 → 一个主指标 + 若干护栏指标；**在查看结果之前**写死阈值。

**判据**：阈值必须是数字，且能回答"多少算过"。

**本仓库实例**：分层 A/B 的主指标是成功率、门禁 `≥0.90`，护栏是摔倒率与完成步数；VLA 侧主指标是 5 任务成功率，护栏是完成步数与失败模式。

**产物**：`docs/EXPERIMENT_DESIGN.md`（预注册，冻结种子与阈值）。

---

### 第 2 步 · 确认数据口径与可测性

**做什么**：先问"这个数记下来了吗、单位对吗、格式对吗"，再写评测。

**判据**：一个 5 分钟的探针脚本能打印出真实的 shape / dtype / 值域 / 量纲。

**本仓库实例**：
- 评测把 robosuite 的 `uint8 HWC (1,360,360,3)` 图像直接喂给按 `float CHW [0,1]` 训练的模型，**不报错、只是成功率恒为 0**；
- `make_libero_env` 取 `suite_envs[0]`，导致 `task_ids=[4]` 直接 `KeyError`；
- 物体位置要穿透 `env._envs[0]._env` 才拿得到，且 `_env` 是懒加载的。

**产物**：`scripts/probe_libero_obs.py`、`scripts/profile_libero_eval.py`。

---

### 第 3 步 · 建立基线与噪声底线

**做什么**：同一配置、同一批种子跑两次，量出"什么都不变时结果差多少"。

**判据**：**噪声大于预期效应时，先加样本或改配对设计，不许下结论。**

**本仓库实例**：同一批 10 个种子两次独立运行分别为 **7/10 和 3/10**；单个种子能在 70 步成功与 280 步超时之间翻转；配对后 **49/100 集结局翻转**。结论：**小于约 15 个百分点的差异，100 集测不出来。**

**产物**：`reports/analysis/audit_*.md`（判别力一栏明确标注"跨 run 混杂，不可用"）。

---

### 第 4 步 · 拆解：把均值切开

**做什么**：按任务、按种子、按进度、按状态、按维度切。

**判据**：每个切片的样本量要写出来；组内方差为 0 的子集要标记为"无分辨率"。

**本仓库实例**：

| 切法 | 结果 |
|---|---|
| 按任务 | task 3 只有 1 个种子稳定成功、8 个稳定失败 |
| 按进度 | 误差在 50% 进度处 0.181，是前后段的两倍 |
| 按状态 | 夹爪闭合时臂部 MAE 0.104 vs 张开 0.077（+35%） |
| 按种子 | 20 个种子里 1 个单独超门禁（0.1627 > 0.15） |

**产物**：`reports/analysis/quantitative_*.md`。

---

### 第 5 步 · 归因：只在同一组内比较

**做什么**：看组内效应量，不跨组混算。

**判据**：组内两组样本各 ≥2 才能估计；估不出来就标"不可估"，**不给跨 run 的合并数字**。

**本仓库实例**：跨 run 混算得到 `track_vx_rmse` 的 Cohen's d = 0.91（"误差大就摔"），实为"RL 组 vs 脚本基线组"的差异；组内一算，摔倒集 0.075 vs 未摔 0.077，**完全一样**。

**产物**：`analysis/audit.py`（辛普森悖论防护，附测试 `tests/test_audit.py`）。

---

### 第 6 步 · 把假设写成可证伪的形式

**做什么**：用"如果 X 是主因，则改 X 后 Y 应变化 ≥Z，配对检验 p < W，且子群 R 不应退化"来表述。

**判据**：带数字、带方向、带反例条件。

**本仓库实例**：夹爪抖动假设 →
> 如果夹爪反复开合是主因，则加入状态锁存后成功率应提升 **≥15 个百分点**，配对 McNemar **p < 0.05**，且 task 3 不应退化。

---

### 第 7 步 · 单变量干预 + 配对复测

**做什么**：一次只改一个变量；同一批种子跑两臂；报配对检验与置信区间。

**判据**：报 Δ、CI、p，不报单点；判定规则沿用第 1 步预注册的阈值。

**本仓库实例**：`n_action_steps` 50 → 25：**55/100 vs 50/100**，Δ **+0.05**，95% CI **−0.09 ~ +0.19**，McNemar **p = 0.57** → 判为"无可靠收益"。同一实验的次要发现：成功集快了 **9.6 步（−8.6%）**。

**产物**：`reports/evidence/vla-2026-11-16/libero_e1_n25.json`。

---

### 第 8 步 · 留档与闭环

**做什么**：负结果入库；把"已排除的假设"写成清单；新指标注册进因子库；算不出的指标变成下一轮埋点需求。

**判据**：每个数字都能追到一个 JSON；每个因子都有定义、方向、阈值、来源。

**本仓库实例**：已排除清单（控制频率 10 Hz、提示工程、重规划频率）；因子库 48 个定义、其中 4 个"待补埋点"就是由"算不出来"反推出来的。

**产物**：`reports/evidence/`、`docs/FACTORS.md`、`docs/RESULTS.md`。

---

## 六个最常见的错误

| 错误 | 后果 | 本仓库实例 |
|---|---|---|
| 只看均值 | 掩盖最差样本 | 均值 0.077 过门禁，最差种子 0.163 超标 |
| 跨组混算 | 得出假因果 | d = 0.91 那条 |
| 单批下结论 | 把运气当能力 | 0.70 实为 0.50 |
| 改口径不记录 | 数字不可比 | 成功率分母用了 `--episodes` 而非实际集数 |
| 樱桃采摘 | 学术诚信问题 | 0.70 若对外报即是 |
| 没有基线就调参 | 调到噪声上 | 曾准备直接花 4 小时重训 |

## 使用检查清单

做任何一次新实验前，逐条打勾：

- [ ] 主指标与阈值已经写下来（第 1 步）
- [ ] 探针确认了数据口径（第 2 步）
- [ ] 基线在同一协议下跑过，噪声底线已知（第 3 步）
- [ ] 计划了切片维度，而不是只看总数（第 4 步）
- [ ] 归因只在组内做（第 5 步）
- [ ] 假设写成了带数字与反例条件的句子（第 6 步）
- [ ] 干预是单变量，评测是配对（第 7 步）
- [ ] 结果（含负结果）已入库，因子表已更新（第 8 步）
